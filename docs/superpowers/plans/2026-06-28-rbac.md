# Full Multi-User RBAC — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:subagent-driven-development.
> Steps use checkbox syntax. Each task ends with an independently testable deliverable.

**Goal:** Multi-user RBAC (users, roles, per-connection grants, admin UI, migration).

**Architecture:** Extend the existing single-password model. New encrypted
`users.json` + `connection-access.json`; sessions carry `userId`; a
`getCurrentUser` helper resolves identity per request; the AI gate ANDs the
connection AI policy with the user's connection access. Migration auto-creates an
`admin` user from the legacy password.

**Tech Stack:** Next.js 16, TypeScript, vitest, playwright, secret-file
encryption (`src/lib/crypto/secret-file.ts`), base-ui components.

## Global Constraints

- Passwords/hashes NEVER leave the server (users API returns no hash/salt).
- Login has NO user enumeration: identical message + timing for unknown-user vs
  bad-password (always run a scrypt compare against a dummy hash on miss).
- Defense in depth: a member without a grant is denied at BOTH the API list and
  the per-action gate.
- Never zero admins; never delete/demote/disable the last admin or yourself.
- All new on-disk files: `0o600`, encrypted via `writeSecretFileSync`.
- Reuse the existing scrypt scheme verbatim: `scryptSync(pw, Buffer.from(saltHex,'hex'), 64)`.
- Destructive approval / kill switch / rate limits stay non-disableable, role-independent.
- Tests set `BAKLAVA_DATA_DIR` to a temp dir + clear the relevant globalThis
  Symbol cache before dynamic `import()`, matching `src/lib/auth/auth.test.ts`.

### Task 1: Users store + migration

**Files:**
- Create: `src/lib/auth/users.ts`
- Test: `src/lib/auth/users.test.ts`
- Reference (read, do not break): `src/lib/auth/store.ts`, `src/lib/crypto/secret-file.ts`

**Interfaces — Produces:**
```ts
export interface UserRecord {
  id: string; username: string; passwordHash: string; salt: string;
  role: "admin" | "member"; disabled: boolean; createdAt: number; updatedAt: number;
}
export interface PublicUser { id: string; username: string; role: "admin"|"member"; disabled: boolean; createdAt: number }
export function publicUser(u: UserRecord): PublicUser;
export function listUsers(): UserRecord[];                       // runs migration on first call
export function getUserById(id: string): UserRecord | null;
export function getUserByUsername(name: string): UserRecord | null; // case-insensitive
export function verifyUserPassword(user: UserRecord, password: string): boolean; // timing-safe
export function createUser(input: { username: string; password: string; role: "admin"|"member" }): UserRecord;
export function updateUser(id: string, patch: { role?: "admin"|"member"; disabled?: boolean; password?: string }): UserRecord;
export function deleteUser(id: string): void;
export function countAdmins(): number;        // enabled admins
export function needsSetup(): boolean;        // true when zero users exist
export function _resetUsersCacheForTests(): void;
```

**Behavior:**
- Storage: `${DATA_DIR}/users.json` via `readSecretFileSync`/`writeSecretFileSync`,
  shape `{ version: 1, users: UserRecord[] }`. Cache on
  `Symbol.for("baklava.usersStore")`.
- Username: lowercased, validated `^[a-z0-9._-]{1,64}$`, unique (throw on dup).
- Hashing: 16-byte random salt; `scryptSync(pw, salt, 64)` hex (mirror store.ts).
- Guards: `updateUser`/`deleteUser` throw if the change would drop enabled-admin
  count below 1 (demote/disable/delete last admin).
- **Migration (in the lazy `load()`):** if `users.json` absent and legacy
  `auth.json` has a non-empty `passwordHash` (read via the existing auth store's
  exported accessor — add `getLegacyPasswordForMigration(): {hash,salt}|null` to
  `store.ts` if needed), create one `admin` user `username:"admin"` reusing
  hash+salt, write `users.json`, and call `revokeAllExcept(null)` from
  `sessions.ts`. Idempotent (only when file absent). Log:
  `console.warn("[baklava] migrated to multi-user: admin user 'admin' created from existing password")`.

- [ ] Step 2: Run it, confirm failure.
